## 1. 业务背景与用户痛点

### 1.1 核心业务场景
用户作为光伏/储能解决方案工程师，在日常工作中频繁参与以下两类会议：
1. **线下现场/圆桌会议**：将手机放置在会议桌中央，多人围坐交流（距离手机 0.5m ~ 3m 不等），包含大量专业工程术语（光伏、储能、PCS、BMS、并网验收）以及频繁的短应答（*“对”、“好”、“可以”* 或 越南语 *“Dạ”、“Ừ”、“Đúng rồi”*）。
2. **中越双语/远程混合交流**：与越南客户或海外团队技术对齐，涉及现场免提通话、越南语/英语/中文混合发言，要求实时显示中文双语字幕，并在会后快速产出会议纪要。

### 1.2 现有系统在会议场景下的核心痛点
1. **麦克风采音失真**：默认开启的 WebRTC 回声消除（AEC）容易误将会议室远处参会人的轻声发言判定为回声削掉；
2. **短应答与断句割裂**：过短的 VAD 切段或无预留时长容易丢掉句首单词（如越语 *“Dạ”*）；
3. **ASR 语境先验幻觉**：将前文未经校验的文本直接送给下一段 ASR 作为上下文，容易在低信噪比下产生“看似流畅但实际没人说过”的虚假台词；
4. **专业术语同音错字**：光伏/储能行业专有名词（如项目名“鹏鼎”、“道达尔”、“六和机械”，技术词“高压柜”、“调频”、“黑启动”）缺少会前热词偏置；
5. **缺少会后结构化交付**：当前仅有流水账字幕列表，缺少按发言人、议题、结论、待办（Action Items）组织的结构化纪要。

## 2. 总体架构与设计原则

> **状态更新 (2026-08-14)**：根据用户确认，**Pass 3 (会后结构化纪要生成)** 暂缓开发，当前优先交付 **Stage 1 (前端采音模式、采样点账本、会议 VAD 调优、ASR 防幻觉提示词)** 与 **Stage 2 (会前热词预设、两阶段声学锁定与热词增强翻译)**。

```text
┌─────────────────────────────────────────────────────────────────────────┐
│                           前端移动端 Web App (iOS Safari / Android)     │
│                                                                         │
│  [会前配置] ──> 会议主题 / 参会人列表 / 行业热词预设                     │
│  [采音控制] ──> 线下圆桌模式 (AEC关/AGC开) | 远程混合模式 (AEC开/AGC开) │
│  [双流协同] ──> PCM Worklet (带采样点账本) ──┬──> WebSocket 实时草稿流 │
│                                             └──> 动态 15-20s WAV 终稿流 │
└──────────────────────────────────────────────┬──────────────────────────┘
                                               │
               ┌───────────────────────────────┴──────────────────────────┐
               ▼                                                          ▼
┌──────────────────────────────┐          ┌──────────────────────────────────────────────┐
│  Pass 1: 实时低延迟字幕      │          │  Pass 2: 准确语音段终稿 (Functions /finalize) │
│  (Gemini Live WebSocket)     │          │                                              │
│  - 200~400ms 快速出字        │          │  Step 2.1: 纯声学 ASR 识别 (严禁语境猜测)      │
│  - UI 实时滚动显示 (浅色/草稿)│          │  Step 2.2: 热词校准 + 语义分句 + 词级时间戳  │
│  - 辅助参会人员实时阅读      │          │  Step 2.3: 结合行业 Prompt 地道直译中文      │
└──────────────────────────────┘          └──────────────────────────────────────────────┘
```

**设计原则**：
1. **渐进交付**：Stage 1 聚焦前端声学控制与 ASR 防幻觉（零后端破坏性改动）；Stage 2 聚焦热词增强与纪要生成（原生 Functions 扩展）。
2. **声学与语言解耦**：ASR 阶段必须“听什么写什么”，不得根据语言模型先验自行编造；翻译与润色放在第二阶段进行。
3. **真实可审计**：每个时间戳、每个采样点、每条发言人归属均保留元数据，可回溯验证。

## 3. Stage 1 详细功能规范（前端采音与声学防幻觉）

### 3.1 会议采音模式切换（Audio Capture Modes）
在会议开始前或设置面板中提供明确的采音模式选择：

| 模式名称 | 适用场景 | `echoCancellation` | `noiseSuppression` | `autoGainControl` |
|---|---|---|---|---|
| **线下圆桌会议（推荐）** | 手机放桌面，多人现场开会 | `false`（避免误杀远端弱声） | `true`（滤除空调/背景稳态噪声） | `true`（自动增益放大远处声音） |
| **远程/免提混合会议** | 手机外放电话会议/视频会议 | `true`（消除喇叭回声） | `true` | `true` |
| **本地音轨直接上传** | 事后录音文件、旁路录音笔 | N/A（直接读取原始无损 PCM） | N/A | N/A |

**技术要求**：
- 采集成功后，调用 `track.getSettings()` 获取浏览器实际生效的硬件参数，并显示在调试状态栏中（例如：`🎤 线下模式 (AEC: off | AGC: on)`）。

### 3.2 采音健康度与采样点账本（Telemetry & Sample Ledger）
解决 iOS Safari 息屏、切后台或性能抖动引起的采音丢失：
1. **AudioWorklet 采样计数器**：
   - 维护单调递增的 `capturedSamples`、`frameIndex` 和 `audioContextTime`。
2. **主线程与 WebSocket 序列校验**：
   - 每次发送 100ms PCM 包时携带递增 `seq`。
   - 会议结束或暂停时，核对：`理论时长 = (当前时间 - 开始时间)` 与 `实际采集时长 = capturedSamples / 16000`。
   - 若有效音频与墙钟时间差异超过 5%，在界面给出黄色提示：*“检测到手机系统节电限制，有约 X 秒音频未被采集”*。

### 3.3 会议 VAD 与边界保护参数
调整 `public/lib/segment-policy.js` 与 `public/lib/adaptive-energy-vad.js`：
- **`PRE_ROLL_MS`**：维持 `500ms`（预留足够前置缓冲，防止漏掉第一个短音节）。
- **`VAD_SILENCE_MS`**：从 `800ms` 微调为 `900ms`（适应会议发言时的正常呼吸与短暂停顿）。
- **`VAD_MIN_SPEECH_MS`**：`150ms`（确保单音节短应答如 *“Dạ”*、*“对”* 能被有效捕获）。
- **`MAX_SEGMENT_MS`**：`15000ms ~ 20000ms`（自适应切段，若连续发言超过 15 秒且检测到能量波谷时平滑切断，保证整句语义完整）。

### 3.4 二次终稿 `/finalize` 提示词防幻觉改造
修改 `functions/finalize.js` 中的 Gemini 批量提示词：
1. **严格事实听写要求**：明确告知模型：“你是一名严格的法庭/会议速记员。只转写音频中真实发音的内容。如果音频模糊、低信噪比或背景音，输出实际听到的声音或标为 uncertain，严禁根据前后文猜测或补全未发音的台词。”
2. **上下文隔离**：历史上下文仅作为“专有名词参考与说话人语境参考”，ASR 输出必须以当前音频事实为最高优先级。

## 4. Stage 2 详细功能规范（会议热词与结构化纪要）

### 4.1 会前信息与热词注入（Pre-meeting Metadata）
在会议开始弹窗或控制栏增加“会议信息预设”输入区（可折叠、自动保存至 localStorage）：
- **会议主题**：如 *“鹏鼎 35MW 储能电站调试进展与并网沟通”*
- **参会人员**：如 *“戴总、孙宇、叶工、阮工（越南方代表）”*
- **行业/项目热词**：如 *“PCS、BMS、并网柜、总平间距、越南六合、道达尔、削峰填谷”*

### 4.2 两阶段终稿处理流水线（Two-Stage Refinement）
在 `functions/finalize.js` 中将处理分为两部分（可通过单次结构化 JSON 提示词或串联方式完成）：
1. **阶段 1：声学转写**：
   - 结合热词偏置，输出精准的原文（保持多语言真实发音，如越南语、英语或中文）。
   - 提取段内估计的句子边界与词级时间戳。
2. **阶段 2：地道直译与工程润色**：
   - 结合工程术语表，将外语直译为符合电力/储能行业惯用语的中文（例如：避免将 *“bình”* 机械翻成“瓶子”，在电气语境下结合热词校准为“容器/电池舱/油箱”；避免将 *“vái/cúng”* 误翻为“价格”）。

### 4.3 会后结构化纪要生成器（Meeting Summary Engine）
新增 Cloudflare Functions 接口 `/summary` 与前端面板：
1. **请求入参**：
   - `meetingTitle`、`participants`、`hotwords`、`finalTranscripts[]`（全场已确认终稿列表）。
2. **输出规范（Markdown 格式）**：
   - **一、会议概况**（时间、主题、参会人员）
   - **二、核心讨论要点**（按议题聚类，归纳 3-5 个核心要点）
   - **三、关键决策事项**（明确记录达成的共识）
   - **四、待办事项清单（Action Items）**：表格形式，包含 `序号 | 待办内容 | 责任人 | 计划完成时间`
   - **五、完整发言时间线记录**
3. **前端导出能力**：
   - 支持一键复制标准 Markdown。
   - 支持下载 `.md` 文件。
   - 格式直接兼容现有飞书文档导入规范。

## 6. 测试与真机验收标准

### 6.1 自动化测试矩阵（TDD）
- 运行 `npm test`，覆盖所有单元测试（`pcm-chunker`, `adaptive-energy-vad`, `finalize-function`, `summary-function` 等），断言通过率 100%。

### 6.2 移动端真机验收场景（Safari / Chrome）
1. **安静会议室 3 米远场测试**：
   - 手机放桌子一端，人在 3 米外中等音量发言，验证 `线下圆桌模式` 能否正常触发 VAD 并识别出完整句子。
2. **高频短应答测试**：
   - 连续进行多轮简短对话（*“好的”、“收到”、“明白”、“Ừ”、“Dạ”*），验证短词是否被丢弃或截断。
3. **专业热词测试**：
   - 预设热词 *“鹏鼎储能、高压并网柜、道达尔”*，口述相关技术讨论，验证终稿文本是否正确命中专业词汇。
4. **会后纪要生成测试**：
   - 录制 2~3 分钟多议题讨论，点击结束并生成纪要，验证是否准确提炼出待办与责任人。
